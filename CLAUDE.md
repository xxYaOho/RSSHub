## Architecture

RSSHub is an RSS feed aggregation server built with **Hono** (TypeScript). It scrapes web content and produces RSS/Atom/JSON feeds via a plugin-style route system.

### Route auto-discovery (`lib/registry.ts`)

Routes are NOT manually registered. They are auto-discovered from `lib/routes/<namespace>/`:

- **Dev** (`NODE_ENV=dev`): dynamic filesystem scan via `directoryImport()`
- **Production**: imports pre-built `assets/build/routes.js` (generated by `scripts/workflow/build-routes.ts`)

Each directory under `lib/routes/` becomes a namespace. Modules export one of three things:

- `route: Route` — a feed route (GET `/:namespace/:path`)
- `namespace: Namespace` — metadata for the namespace (name, url, lang)
- `apiRoute: APIRoute` — an API route (GET `/api/:namespace/:path`)

Literal path segments take priority over `:param` segments during sorting.

### Request middleware pipeline (`lib/app-bootstrap.tsx`)

Middleware runs in this exact order on every request:

1. `trimTrailingSlash` → `compress` → JSX renderer → logger → trace → honeybadger → sentry → `accessControl` → `debug` → **`template`** (converts `Data` to RSS/Atom/JSON output) → `header` → `antiHotlink` → `parameter` (query params: limit, format, filter etc.) → `cache`

Route handlers set `ctx.data` via `ctx.set('data', result)`. The `template` middleware reads `ctx.data` and renders the feed. If the handler returns a `Response` directly, the rest of the pipeline is skipped.

### Route file structure

Every route file exports a `route: Route` object and a `handler` function:

```ts
import type { Route } from '@/types';
import ofetch from '@/utils/ofetch';
import { parseDate } from '@/utils/parse-date';
import cache from '@/utils/cache';

export const route: Route = {
    path: '/topic/:id',
    categories: ['new-media'],
    example: '/mysite/topic/250',
    parameters: { id: '专题 id' },
    features: {
        requireConfig: false,
        requirePuppeteer: false,
        antiCrawler: false,
        supportBT: false,
        supportPodcast: false,
        supportScihub: false,
    },
    radar: [{ source: ['mysite.com/topic/:id'] }],
    name: '专题文章更新',
    maintainers: ['your-github-username'],
    handler,
};

async function handler(ctx) {
    const id = ctx.req.param('id');
    // fetch data, parse, build items...
    return { title: '...', link: '...', item: [...] };
}
```

The handler receives a Hono `Context` and returns a `Data` object (`{ title, link, description?, item: DataItem[] }`), or a `Response` for direct control.

### Namespace metadata

Each namespace directory needs a `namespace.ts`:

```ts
import type { Namespace } from '@/types';
export const namespace: Namespace = {
    name: '网站名',
    url: 'example.com', // no https:// prefix
    lang: 'zh-CN',
};
```

### Key utilities (all under `lib/utils/`)

| Import                                | Use                                          |
| ------------------------------------- | -------------------------------------------- |
| `ofetch` from `@/utils/ofetch`        | HTTP requests (preferred over `got`)         |
| `got` from `@/utils/got`              | HTTP requests (legacy, still widely used)    |
| `cache` from `@/utils/cache`          | `cache.tryGet(key, fn)` for per-item caching |
| `parseDate` from `@/utils/parse-date` | Parse date strings to timestamps             |
| `config` from `@/config`              | Runtime config (env vars, defaults)          |

### Config system (`lib/config.ts`)

All config via environment variables. `config` is a frozen object computed at import time. Key env vars:

- `PORT` (default 1200), `CACHE_TYPE` (memory/redis), `REDIS_URL`
- `ACCESS_KEY` — if set, required as `?key=` or `Authorization: Bearer` header
- Route-specific credentials: `BILIBILI_COOKIE_*`, `GITHUB_ACCESS_TOKEN`, `TWITTER_*`, etc.
- `DEBUG_INFO` (default `'true'`) — enables debug endpoints

## Critical conventions

- **Never add routes to `lib/router.js`** — it's deprecated. All routes go in `lib/routes/<namespace>/`.
- **Use `import type`** for type-only imports. Sort imports (oxlint enforces this).
- **Always wrap per-item detail fetching in `cache.tryGet()`**.
- **`example` must start with `/`** — it's a route path, not a full URL.
- **`radar[].source` has no `https://` prefix** — use `'www.example.com/path'`.
- **Single category** in `categories` array (pick one from the `Category` union in `lib/types.ts`).
- **No custom pagination or filtering** — RSSHub has built-in `?limit=`, `?filter=`, etc.
- **Prefer API endpoints over HTML scraping** when the target site has one.
- **`description` is content only** — title, author, pubDate go in their own fields.
- **Don't fake dates** — leave `pubDate` undefined if the source has no date.
- **Writing tests:** Use `vitest` with `msw` for HTTP mocking. Route integration tests live in `lib/routes.test.ts`.
- **No `README.md` or separate `radar.ts`** in route directories — use `Route.description` and `Route.radar`.

## TypeScript

- Path alias `@/` maps to `lib/`
- `Data`, `DataItem`, `Route`, `Namespace` types are in `lib/types.ts`
- `ctx` parameter in handlers is Hono's `Context` type (import from `hono` if needed)

## Developing a new route — practical workflow

### 1. Research the target site

按优先级依次尝试:

1. **WordPress REST API**: `/wp-json/wp/v2/posts` — 如果可用,直接调 API
2. **内嵌 JSON**: 查看 HTML 中 `<script>` 标签是否有 `var xxx = "[{...}]"` 格式的数据,用 `response.match(/var foo = "(.+?)";/s)` 提取,然后 `JSON.parse(JSON.parse(`"${raw}"`))` 解码
3. **静态 HTML**: 用 `ofetch` + `cheerio` 抓取
4. **JS 动态渲染**: 如果静态 HTML 缺内容,用 Playwright 浏览器打开确认 DOM 结构,再决定是否需要 `requirePuppeteer`

用 Playwright (`browser_navigate` + `browser_evaluate`) 看真实 DOM,不要仅依赖 WebFetch (它只返回渲染文本,不反映 JS 动态内容)。

### 2. Choose the scraping strategy

- **列表有日期/作者** → 直接从列表提取,不进详情页
- **列表只有标题+链接** → 两阶段: 列表提取 + `cache.tryGet()` 进入详情页补全 date/description
- **每篇文章内容都不同** → 必须进详情页取 description

### 3. Test as you go

```bash
# Direct Hono app test (fast, no network deps)
echo "import app from './app.js'; const r = await app.request('http://localhost/uisdc/news'); console.log(r.status)" | pnpm tsx -

# Curl test against running server
curl -s --noproxy '*' http://localhost:1200/uisdc/news | head -20
```

**注意**: macOS 有代理环境变量 (`http_proxy`) 可能干扰 curl。加 `--noproxy '*'` 避免。

Docker 容器和 dev server 都占用 1200 端口时,curl 可能打到 Docker (不含新路由) 而非 dev server。用 `lsof -i :1200` 确认谁在监听。

**RSS 代理路由**: `/proxy/rss?url=<外部RSS地址>&chatgpt&limit=5`

- 抓取任意外部 RSS/Atom feed, 透传 RSSHub 中间件
- 配合 `?chatgpt` 参数实现双语翻译
- `?limit=N` 控制首次加载量, 避免本地 LLM 并发压力

### 5. Clean up after development

```bash
# 删除临时测试脚本
rm -f lib/test-*.ts

# 确保没有残留旧进程占用端口
pkill -f "tsx.*lib/index" 2>/dev/null
lsof -i :1200 2>/dev/null | grep LISTEN

# 重新干净启动
CACHE_TYPE=redis REDIS_URL=redis://localhost:6379/ pnpm dev
```

**常见残留进程来源:**

- `dev:cache` (NODE_ENV=production) 启动失败后会残留,因其缺少 `assets/build/routes.js`
- Docker `rsshub-rsshub-1` 容器占 1200 端口
- 多次 `pnpm dev &` 后台累积,`tsx watch` 的子进程不会随终端关闭自动退出

规律: 如果 curl 返回 `503` + "Welcome to RSSHub!" HTML,说明端口上的进程不是当前 dev server,用 `lsof -i :1200` 排查。
